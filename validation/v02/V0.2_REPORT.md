# OPTIVANCE V0.2 — Rapport d’implémentation et de validation Storage

**Date :** 11 novembre 2026  
**Périmètre :** module Storage uniquement, prototype local V0.2.  
**Phase 1 formelle : non commencée.**

## Résumé

Le module Storage V0.2 est compilé en Release et a été lancé sur le poste Windows 11 x64 de développement. Il réalise un scan classique Rust via Named Pipe v2 ACL, affiche un index plat interactif et une treemap squarified construite à partir des tailles du scan. Un scan de `src` a affiché 123 fichiers et 28 dossiers, sans avertissement; les lignes, les totaux, le chemin courant et les rectangles correspondaient aux données remontées par le moteur.

Deux mesures V0.2 finales de `C:\` ont terminé en 70,186 s et 69,456 s, contre 82,895 s et 80,325 s mesurés avant les changements. Voir [le rapport de benchmark](V0.2_BENCHMARK_REPORT.md). Ce progrès est mesurable mais ne démontre pas la parité avec WizTree.

## Non testé — ne pas considérer comme terminé

- Windows 10 Enterprise LTSC 2019/2021 : aucun hôte ou VM cible disponible pour cette mission; Windows 11 ne valide pas LTSC.
- Dossiers inaccessibles en test ciblé; les 717 avertissements du scan de `C:\` n’ont pas été conservés avec leur chemin et ne constituent pas un test ciblé reproductible. Le test concurrent ciblait un fichier supprimé, pas un dossier refusé par ACL.
- Fichiers renommés pendant l’analyse et volumes contenant des dizaines de milliers d’entrées avec rendu WPF/treemap simultané.
- Annulation par le bouton WPF, fermeture de la fenêtre pendant l’analyse, navigation rapide répétée et navigation/tri fluide dans une grande arborescence.
- Affichage temporisé de l’infobulle treemap. Le code met à jour l’infobulle au survol, mais l’apparition n’a pas été confirmée dans la capture.
- Exécution des commandes Ouvrir, Ouvrir l’emplacement, Copier le chemin, Copier le nom et Propriétés.
- MFT/USN : aucun prototype, aucune ouverture de volume brut, aucun test de privilège ou de pop-up UAC.

## Problèmes corrigés

- Styles sombres cohérents ajoutés aux états normaux, survolés, sélectionnés, désactivés et focus; ComboBoxItem générés, DataGrid, menus contextuels, champs, boutons et menus sont stylés.
- L’erreur XAML de menu imbriqué a été corrigée en attachant les menus de lignes dans `LoadingRow`.
- L’index du scan est plat : parent, plage enfant, noms et tailles, ce qui réduit la répétition des chemins dans l’IPC.
- Les résultats sont transmis en lots de 512; lecture/écriture pipe tamponnées; l’annulation et les mises à jour de progression sont moins fréquentes.
- Les chemins dépassant `MAX_PATH` sont préfixés `\\?\` (ou `\\?\UNC\` pour UNC) lors de l’appel Win32 `CreateFileW`; le cas de 415 caractères passe sans avertissement.
- La treemap utilise une disposition squarified asynchrone, un index spatial pour le hit-test et les tailles logiques uniques; les alias hardlink ont un poids nul.
- Grille virtualisée avec tri numérique; navigation, breadcrumbs, sélection synchronisée et menu de ligne ajoutés.
- La légende affiche les catégories Dossiers, Documents, Images, Vidéos, Audio, Archives, Applications, Code et Autres. Cette dernière modification XAML est compilée en Release; sa mise en page finale reste à vérifier visuellement.

## Limites connues

- Une erreur d’identité de fichier/accessibilité entraîne un avertissement et peut empêcher la déduplication d’un hardlink concerné; ne pas présenter cette entrée comme parfaitement dédupliquée.
- Le pic mémoire du benchmark n’inclut pas l’application WPF; l’index complet V0.2 est conservé en mémoire.
- Le probe de référence V0.1 sous `validation/v01-v02a/ScanProbe` est conservé comme artefact historique et cible l’ancien modèle `ScanEntries`; il n’est plus compatible avec le modèle V0.2. Utiliser le nouveau probe `validation/v02/ScanProbe` pour reproduire les mesures actuelles.
- Le worker scanne une arborescence de 20 001 entrées, mais le rendu treemap/DataGrid WPF pour cette taille n’a pas été mesuré; la treemap calcule tous les rectangles enfants, même si la grille des résultats est virtualisée.
- Le menu contextuel apparaît sombre mais la capture montre une marge claire à vérifier; aucune commande destructive n’est déclenchée depuis ce menu.
- La distribution reste un binaire de développement dépendant du runtime .NET Desktop installé. Aucun installateur ni bundle self-contained n’a été créé; le modèle/licence de distribution D-16 demeure ouvert.
- Les autres modules restent des espaces réservés; ils n’ont pas été développés dans cette mission.

## Verdict

**Fondation Storage V0.2 compilable et utilisable pour l’analyse classique sur Windows 11, sous conditions.** Le worker a des preuves réelles pour l’annulation, les hardlinks, un fichier sparse de 5 GiB, les chemins de 415 caractères, une grande arborescence et une suppression pendant le scan. La mission V0.2 n’est pas entièrement close : les interactions WPF pendant un scan, les commandes contextuelles, l’infobulle, le rendu final de la légende et la treemap/DataGrid sur une grande arborescence restent à valider avant de déclarer ces détails terminés.

La Phase 1 formelle n’a pas commencé. Aucun commit ni push n’a été effectué. Aucun nouveau package NuGet ou crate Rust n’a été ajouté.
